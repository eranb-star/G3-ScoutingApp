## Implemented and tested locally

`backend/supabase/g3_assist_budget_20260920.sql` creates a backend-only reservation ledger and singleton policy for this single-team installation. Monthly limit is 25,000,000 integer USD microdollars ($25), disabled initially. This migration cannot raise the ceiling above the user-authorized amount. A higher approved ceiling requires a reviewed migration; future admin settings may lower it or pause execution.

Months use UTC calendar boundaries, no rollover allowance. Unknown dispatched charges from prior months continue to withhold capacity until reconciled. The admin UI must display the exact reset time locally; this is an application accounting period, not an assertion about Google's billing timezone.

Only the service role may reserve, dispatch, stop or settle attempts. Authenticated clients cannot write balances or supply prices through these RPCs. Admins may read ledger/policy via RLS. Reservations and state transitions lock the same policy row, preventing independent workers from allocating the same remaining dollars. Each attempt carries member/request/step identity, input hash, provider/model and price version. Duplicate reservations reuse the same attempt; changed parameters conflict. Only the first successful dispatch claim returns true. Permission, active membership, expiration, month boundary and a lowered cap are checked again before dispatch.

Cancelling an undispatched reservation releases it. Cancelling/timing out a dispatched attempt retains its amount as uncertain. Settlement requires complete usage translated using the recorded price version, including paid tools; unknown usage is never treated as zero. An actual cost greater than its reservation is recorded and disables new work. This cannot undo an already incurred overage: correctness of provider cost bounds is an activation requirement.

`node scripts/test-assist-budget.mjs` passed against the actual migration in PGlite: disabled default, permissions, invalid input, $25 boundary, duplicate/conflicting requests, eight submissions for the last $1 (one accepted), duplicate dispatch, uncertain-charge retention, settlement, revoked access, lowered limit, expiry, month rollover and estimator-failure pause. PGlite serializes queries; this is not a hosted multi-connection contention test. Migration rerun preserves policy settings and ledger rows.

## Not yet active / remaining integration

**Latest continuation:** the working-tree handler now calls the ledger-backed `budgeted-gemini.ts` adapter when the server-only `G3_ASSIST_EXECUTION_MODE=budgeted-text-v1` is selected. Default remains legacy; no environment was changed. The ledger/adapter are not installed in hosted QA/production. Existing production calls are not covered. Do not enable provider billing yet. The separate protection release commit `1bf299b` deliberately does not include this experimental pilot.

The text adapter uses `generateContent` (not the legacy Interactions loop), one candidate, 2,000 combined output/thinking tokens, a 45-second abort deadline, no automatic retry/fallback, no images/tools/cache storage, and provider token counting on the same request structure before generation. Context admission is 16,000 counted tokens / 64,000 UTF-8 bytes. All paid generation must win the ledger dispatch claim. Exhausted/disabled/stale configuration sends no provider requests; failed budget execution never falls back to legacy. Frontend sends a UUID per submission. Execution-level stored-result replay and durable cancellation remain pending; repeated submissions with the same ID cannot generate twice but currently return an already-processed/conflict response.

Pricing verified from Google's primary documentation: Gemini 3.6 Flash Standard $0.75/million input and $3.75/million output (including thoughts) through 2026-12-31. Adapter price version expires 2026-10-20 for re-review, earlier than the announced price transition. Integer quarter-microdollar arithmetic rounds the total upward. No cache/free allowance discounts assumed. The initial conservative reservation is **$0.793932 per attempt**, based on the model's documented maximum input and 2,000 output tokens, even though counted context is much smaller. This is a temporary hold, not a flat charge; complete actual usage settles it. It can decline a question with less than that remaining. Do not describe this conservative adapter as the final budget UX; tighter proven input bounds remain to be implemented/evaluated. countTokens estimates are not treated as a guaranteed billing bound.

Missing/inconsistent usage, network errors and provider errors retain uncertain charges. Explicit thinking counts are required; omission fails conservatively and needs reconciliation. Incomplete output still settles its known charge but is not presented as a complete answer. Only never-dispatched expired reservations are safely released during future allocations under the same database lock. Two concurrent duplicate callers in the local adapter test cause exactly one generation call; the losing caller cannot refund the winner's reservation.
