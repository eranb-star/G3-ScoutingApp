# Fundraising & Production — 4 October 2026

## Scope and navigation
Work → Team Operations → Fundraising & Production (`/fundraising`). English/Hebrew, responsive workspace. Existing inventory managers operate; all active members can read; administrator required for Finance posting. No new default role permissions were granted. User chose **ILS 0.50 per attempted printed item** as editable default operating cost; individual product override supported. This is a planning/recording workspace, not a printer controller or payment processor.

## Flows
- Products: name, optional http(s) model link, instructions, multiple inventory-linked filament rows with grams/item, operating cost, other unit cost, sale price, live estimated unit cost/profit. Archive/restore and revision-checked editing. No second filament catalogue.
- Print jobs: product, quantity, optional event, owner, due date, printer label, notes. Immutable recipe/cost snapshot. Planned → printing → succeeded/partial/failed; planned cancellation; failed quantities can be replanned. Started jobs must account for good + failed = planned. Actual material grams include support/purge/failures. Defaulted planned grams must be confirmed/edited. Failure reason required.
- Material planning: available, active-print reservations, total planned demand, shortages, equivalent whole spools. Link to the existing inventory item's purchasing/receiving actions. Purchase/finance approval flows are reused, not bypassed or duplicated.
- Starting jobs reserves enough material; finishing atomically consumes actual grams and creates stock movement notes. A DB trigger prevents ordinary stock withdrawals consuming active print reservations. Insufficient actual stock rolls back the entire result. No duplicate result deduction.
- Finished units form a shared product stock pool (event assignment is planning metadata, not isolated storage). Sales cannot exceed available stock. Cash/digital methods, actual sale price, stable sale IDs. Voiding unposted incorrect sales restores stock and retains reason; this is not a payment refund.
- Events: planned/open/closed; record sales while open, review totals and cash/digital split, close, then admin posts one income row to existing finance_income. Posting is idempotent. Posted events/sales are locked; later financial corrections need an administrator in the Finance workflow.
- Results: revenue, production contribution (revenue less all completed-job costs including unsold stock), success rate and product CSV. Cost includes actual material usage at job snapshot price plus estimated operating/additional costs per attempted unit. This is NOT cash/net accounting profit. Filament purchases already produce Finance expenses; material consumption does not create duplicate expenses. Other event expenses stay in Finance.

## Deliberate boundaries / next work
No printer telemetry, printer control, slicer/model file hosting, tax invoices, payment collection, physical spool identity, or automatic reimbursements. Existing permissions administration can delegate manage_inventory to responsible roles. No new APK in this release. Physical print results are supplied by the responsible person; app does not detect success by itself. Event expenses are recorded in existing Finance, not automatically allocated to this workspace's contribution estimate. Do not describe estimated contribution as audited net profit.
