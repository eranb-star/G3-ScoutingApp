# Robot Build — team workflow

## Leader: start a build
1. Open Robot Build and select the existing project. Use Build details to identify the season/offseason robot, mechanism or prototype. A complete Onshape robot is not required.
2. Open Assemblies & parts. Create the assembly and optional child assemblies, responsible person and due date.
3. Add a manual requirement or import reviewed CAD through CAD Mentor. Imported lists remain private until explicitly shared. Assign existing requirements to assemblies instead of adding them again.
4. Enter total pieces needed across this build. Assembly quantities are organizational context, not an extra multiplier.
5. Review each part's source: make, use inventory, purchase, or exclude with a reason. Where needed, use combined sourcing before execution: six plates can be two from stock and four to manufacture. Divide existing assembly assignments between those sources in the same form.
6. Plan manufacturing from the selected part. Assign worker and reviewer, instructions, exact revision, and acceptance checks. Complete the existing release/material/file prerequisites before starting manufacture.

## Student: do assigned work
1. Open the dashboard's assigned work or Workshop → My work.
2. Open a task. Read its instructions and controlled files before starting.
3. Record operations and actual progress. Report a problem when blocked; do not enter planned quantities as completed quantities.
4. Submit inspection evidence. The independent reviewer accepts or requests corrections. Completion reports do not automatically become accepted inventory.
5. Follow the existing lot/rework/scrap controls for partial results. Material is not automatically refunded after failure.

## Leader and reviewer: assemble and test
1. In Assembly & testing, choose Plan assembly & test. Select an assembly with defined requirements and reviewed sources. Manufactured requirements must already identify their released job.
2. Assign a worker and independent reviewer, assembly instructions, assembly acceptance and bench-test acceptance. Include physical test/demonstration criteria.
3. Open its component kit and issue suitable accepted components. The assembly inspection cannot be submitted with missing planned components.
4. Submit assembly evidence and obtain approval, then perform the dependent bench test and record its evidence.
5. When a reviewer requests changes before installation planning, use Correct a failed inspection or bench test → Reopen for correction. Both assembly and bench approval must be renewed. Previous failed evidence remains in history.
6. Installation is optional and separate. After assembly and bench approval, plan robot installation. Submit evidence against the exact physical robot configuration before recording installation. Once installation is planned, use the existing installation replacement/retest workflow for later component changes.

## CAD and inventory boundaries
- Open CAD from a requirement to inspect its recorded snapshot. The return link restores the build context. A newer Onshape revision does not silently replace approved manufacturing evidence.
- Inventory, purchasing, tasks and reviews remain the existing shared systems. Build quantities organize demand; stock is reserved/issued only through the stock actions.
- Mixed sourcing cannot rewrite a requirement with allocation, purchase, manufacturing or kit history. Executed history is retained.
- Equipment is an operation resource, not a consumed robot component.
- Phase 2 placement/drag-and-drop, robot mass calculation and simulator synchronization are not part of this release.

## Acceptance boundary
Automated fixtures validate software transitions with synthetic evidence. They do not certify actual manufacturing, safety, measured robot performance or an uncoached student usability trial. Record genuine results during workshop use.
