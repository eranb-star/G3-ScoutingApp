## Proposed priorities (bounded first increments)
1. Guided student engineering and learning in existing Skills Academy/Work/G3 Assist. Pilot intake and shooter troubleshooting with prerequisites, evidence-linked explanations, stepwise measurement prompts, hints, practical demonstration rubrics, remediation and next tasks. Reuse assessments/review; human review retains physical qualification authority. Acceptance: a student completes a diagnosis/exercise, explains evidence, submits a result and receives the next learning action through one flow. Start without private repo/logs using explicitly labelled reference examples and existing team content. Existing AI access must not silently expand to students; curated activities work without direct paid AI access, any future student tutor entitlement needs explicit role/budget design.
2. Shared real-robot test and improvement records. Add versioned robot/configuration-linked test sessions, units, conditions, trial counts, outcome definitions, measurements, uncertainty and proposed fixes connected to existing tasks. Begin manual/CSV entry and guided measurement protocols; automated logs follow actual samples. Pilot intake/cycle/shooting and autonomous completion consistency. Acceptance: compare like-for-like repeated runs before/after one change, with simulated versus physical evidence unmistakable. Never infer success probability from one run.
3. Repository/log-connected Software Mentor and autonomous integration. Connect actual repo revision/build/libraries/subsystem commands; implement the exported scaffold's adapter or a selected supported trajectory integration; isolated builds/tests, reviewable changes and one supported log format with timestamped diagnosis. Acceptance: code builds against the real project and observed data supports findings; workshop validation remains separate. Inputs required. Camera calibration should be integrated here when actual hardware/detections arrive, not another placement UI.
4. Pit reliability and return-to-field workflow. Extend the existing queue/assignments/inventory/review with configuration-aware preflight, recurring failure linkage, repair/retest evidence, critical spares and one concise readiness view. Reuse existing offline paths. Acceptance: a fault moves from report to owner to repair to retest to readiness, with responsible sign-off and no duplicate task system. Verify existing schema/workflow gaps before scope commitment.
5. Adaptive driver/operator/drive-coach training. Extend existing drills/match rehearsal/replay with repeatable mission scoring, route/heading consistency, explicit robustness scenarios and shared comparable progress. Preserve run parameters and separate measured variation from hypothetical perturbations. Acceptance: same exercise before/after training produces interpretable results. Physical logs calibrate claims; VR headset/device checks required. Full tower/foul/six-robot rules are separate increments.
6. Mechanical/electrical design and manufacturing support. Version-linked requirements, calculations with units/assumptions, CAD/BOM/drawings, design comparisons, QC/install/spare traceability. Reuse workshop/inventory/task approvals. Begin one subsystem, not arbitrary robot/CAD generation. Acceptance includes physical fit/measurement and responsible review; actual private CAD is an input for team-specific claims.
7. Season transition readiness and later competitive extensions. Existing Check now remains. Remaining work is reviewed field/assets/tags/rules/simulation adapter readiness and old/new-season isolation; novel mechanics may need code. Follow with alliance planning/scouting-derived strategy once own-team readiness is demonstrated, and evidence-based awards/outreach/sponsor continuity in existing operations where concrete gaps are found.
