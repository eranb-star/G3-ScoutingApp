## Product placement and flow
Canonical home: Work → Engineering Hub → CAD Mentor. Academy assignments link to this same review; Robot Learning Lab remains reference learning; Field & Robot Studio consumes an explicitly selected reviewed geometry revision and robot profile. Knowledge supplies cited manufacturer/rule evidence. No duplicate libraries or separate findings in each area.

Flow: connect → select documents/folders → choose design and purpose → review → inspect finding → assign/propose correction → update in Onshape → refresh and verify. Support sketch, part, mechanism, partial robot and complete robot from the start. User specifies season/project, intent, material/manufacturing process and required load/motion only where needed; missing information blocks dependent checks, not viewing or all other checks.

UI: library with thumbnails and meaningful aliases, type, owner, synced revision, changed badge. Review has compact source/revision toolbar, collapsible component tree, dominant 2D/3D canvas, compact finding panel. Fullscreen retains selection, measure, isolate, section, findings, reset and exit. Sketches use a readable 2D view. Four destinations: Design, Findings, Changes, Requirements. EN/HE and RTL, keyboard navigation, consistent control alignment and mobile bottom sheet. Avoid giant settings panels and unexplained numeric risk scores.

## Connection and data architecture
Register an Onshape OAuth app; request minimum supported read/export scope, validate exact endpoint scopes/plan before promising availability. Server-only encrypted tokens, refresh rotation, OAuth state binding, allowed host checks, team/document allowlist, existing membership plus explicit CAD permissions, signed private asset URLs, audit and revoke/disconnect. Connecting one user's account must not silently share all their private documents. Admin explicitly chooses imported documents and G3 readers. AI disclosure authorization for private CAD is separate from the previous private robot-code grant.

Discover paginated company folders/documents, shared sources and dependencies; report inaccessible references and excluded items. Resolve every review to immutable microversion/version plus configuration, element IDs and instance path. Stable part/feature anchors need remapping after changes; mark unresolved anchors rather than moving a finding to a wrong face. Preserve source units and robot coordinate transform explicitly. Do not merge separate documents into one assembly without known transforms.

Ingest structured sketches/features/constraints and assembly metadata where supported; keep exact geometry for measurements and lightweight glTF/GLB for display. GLB alone is insufficient for engineering correctness. Onshape documents glTF/Parasolid translations; prove export and identity preservation on representative private documents. Background job queue handles conversion, API limits, retries/cancellation and partial failures. Cache by immutable revision/configuration; lazy-load geometry, limit LLM context and show review cost. Store metadata/findings in DB and meshes in private object storage, not Git/public Vercel assets.

Suggested records: cad_connections, cad_sources, cad_snapshots, cad_entities, cad_requirements, cad_review_runs, cad_findings, cad_proposals. Each run records input revision, available/absent evidence, checks and versions, coverage, rule-pack version and model version. Findings attach to existing task/review/evidence flows rather than duplicating them.

## Analysis and corrections
Separate deterministic measurements/checks, explicit requirement rules, and LLM reasoning. LLM explains retrieved evidence and proposes options; it must not invent measurements, materials, torque/load ratings or checks it did not run. Findings show affected part/feature, measurement/unit and source, condition, consequence, severity, evidence class, proposed fix, tradeoff and verification step. Status: open, assigned, proposed fix, awaiting verification, resolved, accepted with reason; changed inputs make prior conclusions stale.

Sketch checks: accessible constraint/dimension state, design intent and layout questions. An underconstrained sketch may be intentional. Part checks: confirmed feature errors, missing inputs, dimensions/holes/walls versus selected manufacturing constraints. Assembly checks: interference, required clearances, tool/battery access and sampled motion envelope where mates/travel exist; distinguish intended contact and conservative mesh candidates from exact interference. System checks: component envelope/connector access, camera geometry using existing advisor, mass/CG only with adequate material/component data, season rules pinned to reviewed current sources. No wiring correctness from absent wiring and no strength certification without load/material/joint data and validated analysis.

Proposals include exact parameter changes where supported, explanations and before/after preview on a separate proposed configuration. Default is read-only plus instructions/deep links. Native CAD writeback is a distinct later capability requiring scoped authorization, branch/copy isolation, feature regeneration, dependent-check rerun and explicit acceptance; never overwrite students' source. Relocating a component preview is not proof that mounting, wiring or mates work.

## Delivery order and acceptance
1. Onshape connection, complete discovery manifest, versioned private ingestion and sketch/part/assembly viewer; private access/revocation tests and stale/partial import UX.
2. Evidence-grounded part/sketch review, requirements, G3 Assist context, visual anchors, tasks and re-review. Acceptance includes actual-source citations, missing-input behavior, Hebrew and narrow/fullscreen layouts.
3. Assembly fit, service/motion and electronics/camera placement comparisons using explicit envelopes and transforms. Test known clashes, intended contacts, near misses, rotations and units.
4. Constrained correction previews and change verification; optional native writeback only after isolated round-trip validation.
5. Link reviews to Academy practical evidence, inventory/manufacturing and calibrated simulator profiles. No automatic qualification or trusted simulation physics from mesh import.

No physical robot required for steps 1–2. Physical validation remains necessary for manufacturing fit, wiring, load/strength, durability and calibrated robot performance. Existing Onshape subscription UI reports Pro Discovery with 141 days remaining; validate ongoing account entitlement rather than assuming perpetual plan/API access. Do not promise all automated checks merely because the API integration works.
