## Limits and next release gates

- No new Edge function or frontend is deployed. Real authenticated browser-to-Edge acceptance remains: QA accounts exist, but credentials are not retained here. Existing isolated protection candidate `1bf299b` remains unchanged and excludes this increment. These controls remain uncommitted working-tree work.
- Paid semantic relevance evaluation is still required. Twenty EN/HE/ambiguous/misuse cases are prepared in `docs/research/assist-purpose-evaluation.json`; no provider evaluation was run. A classifier is probabilistic and cannot guarantee that no misuse passes. Permissions, spending limits and tool restrictions remain independent controls.
- This pilot uses a 90-second durable execution lease and up to 45 seconds per provider step; two paid steps maximum, no retries/fallback/tools. This differs from the original proposed single 45-second execution contract. SQL rejects steps/results after the lease; it does not forcibly terminate an already dispatched provider operation. Remote cancellation blocks subsequent dispatch but cannot immediately interrupt a different worker's active fetch.
- Team/day, member/day and classifier-specific monetary sublimits, provider-wide pacing/circuit breaker, a fair queue, and tighter proven reservation bounds remain before broad paid rollout. Current classifier/answer conservative holds are about $0.788352/$0.793932, respectively, not flat charges. Declined questions can incur classifier cost. Existing message-count daily limit is not a substitute for declined-attempt spending controls.
- Full historical-corpus retrieval, source-grounded answer/citation validation, existing image-analysis parity and automatic reconciliation are not completed by this control increment. Legacy production traffic still bypasses the new budget path. Do not enable billing on its current key assuming these controls are active.
- Durable result retention and conversation-deletion behavior need explicit acceptance before production: execution JSON currently stores the answer separately from chat messages. Hosted multi-connection contention, worker-loss/reconnection and permission-revocation races also remain.
